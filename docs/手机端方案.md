# 双端落地：桌面 + 手机

> **状态：暂存（2026-11-22）。** 当前只做桌面端；本文档先放着，等要做手机端/同步时再从这里继续。里面已实测过的部分（PWA 三件套、`--serve`、触屏手柄）代码都已经在仓库里，随时可启用。

先给结论：**核心已经是一份跨端同源的 `index.html`**，桌面壳和手机端共用同一套代码。要"真正的双端 App"，缺的不是重写，而是三件事：① 壳（把网页装成应用）② 移动端入口（相册/分享，因为手机不能截别人的屏）③ 数据同步。

## 二、做成"真 App"的三条路线

### 路线 A：PWA（零成本，今天就能装）

已经做完了。发布时只要**把文件夹挂到任意 HTTPS 静态托管**（GitHub Pages / Vercel / 自己的 NAS + 反代），手机打开 → 浏览器菜单「添加到主屏幕」→ 独立窗口、有图标、可离线。

- 要更新：改 `index.html` 传上去，用户下次打开自动是新版（SW 对导航请求走 network-first）。
- 拿不到：应用商店、系统分享菜单、后台任务、相册批量写入。

### 路线 B：Capacitor（一份 HTML → 真的 .apk / .ipa，推荐）

把现有网页原样塞进原生壳，补上"分享进来"和"相册"两个原生入口。约半天到一天。

```bash
# 前提：Node 18+、Android Studio（安卓）、macOS + Xcode（iOS）
mkdir app && cd app
npm init -y
npm i -D @capacitor/cli
npx cap init "评价表拼图板" cn.you.herogrid --web-dir=www
mkdir -p www && cp ../hero-grid-board/{index.html,manifest.webmanifest,sw.js,icon-192.png,icon-512.png} www/
npx cap add android
npx cap add ios          # 需要 macOS
npx cap sync
npx cap open android     # 在 Android Studio 里 Run / Build APK
```

壳里再加两件事（各 20~40 行）：

1. **分享进入**：Android `AndroidManifest.xml` 里给 MainActivity 加 `ACTION_SEND` + `image/*` 的 intent-filter；iOS 加 Share Extension。拿到的 URI 通过 `Capacitor.convertFileSrc()` 变成 `file://` → 直接 `setPending()`。
2. **相册选择**：`@capacitor/camera`（`Camera.getPhoto({ source: 'photos' })`），比 `<input type=file>` 体验好，还能一次多选。

同步：`@capacitor/filesystem` 把"导出 json"落到手机目录，配合网盘同步。

### 路线 C：Tauri 2（桌面 + 移动同一套壳，包体最小）

适合"我想要一个 20MB 以内的真桌面 App，顺便也能出手机包"。桌面端能拿到 **全局热键 + 系统级框选**（`tauri-plugin-global-shortcut` + `xcap`/`screenshots` crate），这正是现在浏览器壳做不到的部分。

```bash
npm create tauri-app@latest
# 前端目录直接用现有 index.html
npm run tauri dev
npm run tauri build              # Windows .msi/.exe
npm run tauri android init       # 移动端
npm run tauri ios init
```

代价：要装 Rust 工具链；前端与 Rust 之间要写一层 command 胶水。

### 路线 D：Electron（只做桌面，最省心）

想要"真·一体化 exe + `Ctrl+Alt+A` 全局框选 + 托盘 + 自动存盘"，这是最短路径：

```bash
npm i -D electron electron-builder
```

```js
// main.js 关键三行
globalShortcut.register('Control+Alt+A', async () => {
  const src = await desktopCapturer.getSources({ types: ['screen'] });
  win.webContents.send('grab', src[0].thumbnail.toDataURL());  // 页面里继续用现成的框选层
});
```

页面侧只需监听 `grab` → `setPending(dataURL)`，其余代码不动。打包 `electron-builder --win portable` 出单文件 exe。

## 三、移动端的能力边界（先说清楚，免得白做）

**手机/平板不能像桌面那样"截别的 App 的屏"。**

- **iOS**：ReplayKit 只能录自己的 App 或让用户手动开始录屏；没有静默抓屏 API。现实链路是「控制中心录屏 → 相册 → 本 App 取帧」，或者用**快捷指令**：`截屏 → 存储到相册 → 打开 App`，一键串起来。
- **Android**：`MediaProjection` 技术上可以（要前台服务 + 每次弹授权，Android 14 起可选"仅此应用"），但只在原生壳里能做，网页永远没有这个权限。

所以移动端的正确入口是这三条，已按优先级排好：

| 入口 | 现在 | 需要什么 |
| --- | --- | --- |
| 相册多选 → 批量填入 | ✅ 已做（🖼 相册） | 无 |
| 系统分享"发送到本 App" | ⬜ | 路线 B（Capacitor）加 intent-filter / Share Extension |
| 剪贴板粘贴（安卓可读图） | ✅ 桌面已做；安卓浏览器大概率可用 | 无 |
| 截屏→相册→App（快捷指令） | ⬜ 用户侧 5 分钟配置 | 无 |

触屏交互取舍：**拖动靠 ⠿ 手柄**（手指按格子会变成滚动画布，这是有意的）；双指缩放画布尚未做，想加的话在 `boardWrap` 上加 `touchstart` 双指 + `transform:scale` 即可。

## 四、数据怎么在两端之间走

现在每端各存各的 localStorage，互不相通。按成本排：

1. **手动搬运（0 开发）**：桌面 `💾 保存` 出 json → 微信/网盘传手机 → 手机 `📂 读取`。图片都在 json 里（base64），单表通常几百 KB 到 2MB。
2. **同步盘目录**：桌面壳里加"自动导出到 `%USERPROFILE%\Nutstore\评价表\最近.json`"，手机端从网盘打开同一份 —— 实质是文件同步，不用写服务器。
3. **WebDAV 直连**（坚果云）：需要一个允许跨域的客户端；网页端会被 CORS 卡住，壳里没这个问题。
4. **自建小同步**：`--serve` 那个 HTTP 服务已经在了，再加 `GET /api/board` 与 `PUT /api/board`，两端点一下"同步"即可（同一 Wi-Fi 场景最省事）。

建议先做 1，觉得烦再上 2。

## 五、下一步建议的顺序

1. **今天**：`评价表拼图板.exe --serve` → 手机同 Wi-Fi 打开 → 添加到主屏幕，先把"手机能看图能排"跑通。
2. **要给别人用**：走路线 B 打 apk（安卓一下午；iOS 需要一台 Mac）。
3. **要全局热键 + 系统框选**：走路线 D（Electron）或 C（Tauri），页面代码基本不动，只加一个"收到图片"的入口。
4. **要两端同步**：先上"同步盘目录"这种土办法，够用且不会引入服务端。
